ลงมือทำทีละขั้น

หน้านี้เขียนสำหรับคนที่ "ยังไม่เคยทำ" — ทุกคำสั่งจะบอกว่าให้รันที่โฟลเดอร์ไหน, ทุกโค้ดจะมีคอมเมนต์ว่าบรรทัดนั้นทำอะไร, และทุกขั้นจะบอกว่า ถ้าถูกต้องจะเห็นอะไร

0. พื้นฐาน terminal ที่ต้องใช้จริง

ข้ามได้ถ้าใช้ terminal เป็นแล้ว — แต่ถ้าเคยเจอ "command not found" ให้กลับมาอ่าน

terminal / command line คืออะไร

คือช่องที่เราพิมพ์คำสั่งเป็นข้อความให้คอมพิวเตอร์ทำ แทนการคลิกเมาส์ ทุกครั้งที่รันโปรเจกต์ Node.js เราจะสั่งงานผ่าน terminal

หน้าตา terminal
C:\Users\ACER\projects\exam> # สิ่งที่อยู่หน้าสุดคือ "โฟลเดอร์ปัจจุบัน" (current directory) # พิมพ์คำสั่งต่อท้ายบรรทัดนี้แล้วกด Enter
3 อย่างที่ต้องรู้จัก
  • โฟลเดอร์ปัจจุบัน — คำสั่งส่วนใหญ่จะทำงานกับโฟลเดอร์นี้
  • path — ที่อยู่ของไฟล์ เช่น C:\projects\exam\server.js
  • exit code — 0 = สำเร็จ, ไม่ใช่ 0 = มีปัญหา (terminal จะแสดง error สีแดง)

คำสั่งที่ใช้บ่อย (Windows PowerShell)

คำสั่งทำอะไรตัวอย่าง
pwd ดูว่าตอนนี้อยู่โฟลเดอร์ไหน pwd → D:\exam
dir (หรือ ls) ดูไฟล์/โฟลเดอร์ในที่ปัจจุบัน dir
cd ชื่อโฟลเดอร์ เข้าโฟลเดอร์ cd exam
cd .. ถอยออกไปหนึ่งชั้น cd ..
mkdir ชื่อ สร้างโฟลเดอร์ใหม่ mkdir exam
node -v ดูเวอร์ชัน Node.js ที่ติดตั้ง node -v → v24.x.x
npm -v ดูเวอร์ชัน npm (ตัวติดตั้งไลบรารี) npm -v → 11.x.x

Ctrl + C หยุดโปรแกรมที่กำลังรันอยู่ (เช่น server) กดในหน้า terminal ที่ server รันอยู่
กฎง่าย ๆ 3 ข้อ
  • คำสั่ง npm และ node ต้องรันในโฟลเดอร์โปรเจกต์ (ที่มี package.json) — ไม่ใช่โฟลเดอร์ไหนก็ได้
  • ถ้าลืมว่าอยู่ไหน ให้พิมพ์ pwd แล้วดู
  • ถ้า terminal ค้าง/ไม่กลับมา ให้กด Ctrl+C — server ที่รันอยู่จะหยุด
กับดักที่มือใหม่เจอบ่อย: เปิด terminal มาอยู่ที่ C:\Users\ACER แล้วพิมพ์ npm start → จะได้ ENOENT: no such file or directory, open 'package.json' แปลว่ายังไม่ได้ cd เข้าโฟลเดอร์โปรเจกต์

พอร์ต (port) คืออะไร

เครื่องหนึ่งเครื่องมี "ประตู" ให้โปรแกรมเปิดรับการเชื่อมต่อได้หลายบาน เรียกเป็นตัวเลข เช่น 3000 — ถ้า server เปิดที่ 3000 เว็บของเราจะอยู่ที่ http://localhost:3000

ถ้าเจอ EADDRINUSE: address already in use :::3000 แปลว่ามีโปรแกรมอื่นใช้พอร์ต 3000 อยู่ (มักเป็น server ตัวเก่าที่ยังไม่ปิด) → ปิดตัวเก่าด้วย Ctrl+C หรือเปลี่ยนพอร์ตด้วย set PORT=3001 && npm start

2. ฐานข้อมูล 2 ตาราง

เลือกโมเดลที่ "มีตารางลูก" ชัด ๆ เพื่อให้ได้ FK และได้คะแนนเรื่อง relation

คิดก่อนเขียน: 1 : N คืออะไร

ตัวอย่างนี้ใช้ categories (หมวดหมู่) กับ books (หนังสือ): หมวดหมู่หนึ่งมีหนังสือได้หลายเล่ม แต่หนังสือหนึ่งเล่มอยู่ได้หมวดเดียว → ความสัมพันธ์แบบ หนึ่งต่อหลาย (1:N)

categories

  • id PK
  • name
  • description
  • created_at
1 ──── N

books

  • id PK
  • title
  • author
  • price, stock
  • cover_url
  • category_id FK → categories.id
ศัพท์ 3 คำที่ต้องพูดได้
  • PK (Primary Key) — คอลัมน์ที่ระบุแถวนั้นแบบไม่ซ้ำ เช่น id
  • FK (Foreign Key) — คอลัมน์ที่ชี้ไปยัง PK ของอีกตาราง เช่น books.category_id
  • ON DELETE RESTRICT — ห้ามลบหมวดหมู่ถ้ายังมีหนังสืออยู่ในหมวดนั้น
db.js 
const path = require("node:path");
const { DatabaseSync } = require("node:sqlite");   // มากับ Node 22.5+ ไม่ต้อง npm install

// เก็บไฟล์ฐานข้อมูลไว้ข้าง ๆ ไฟล์นี้ (library.db)
const DB_PATH = process.env.DB_PATH || path.join(__dirname, "library.db");
const db = new DatabaseSync(DB_PATH);

db.exec(`
  PRAGMA foreign_keys = ON;   // ⚠ SQLite ปิด FK เป็นค่าเริ่มต้น ต้องเปิดทุกครั้ง

  CREATE TABLE IF NOT EXISTS categories (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,  // วิ่งเลข 1,2,3.. เอง
    name        TEXT    NOT NULL UNIQUE,            // ห้ามว่าง ห้ามซ้ำ
    description TEXT    DEFAULT '',
    created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
  );

  CREATE TABLE IF NOT EXISTS books (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    title       TEXT    NOT NULL,
    author      TEXT    NOT NULL,
    price       REAL    NOT NULL DEFAULT 0,
    stock       INTEGER NOT NULL DEFAULT 0,
    cover_url   TEXT,                                // เก็บ "path" ของรูป ไม่ใช่ตัวไฟล์
    category_id INTEGER NOT NULL,
    created_at  TEXT    NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE RESTRICT
  );

  CREATE INDEX IF NOT EXISTS idx_books_category ON books(category_id);
`);

// seed ข้อมูลตัวอย่าง (ทำครั้งเดียวตอนที่ยังไม่มีข้อมูล)
const count = db.prepare("SELECT COUNT(*) AS c FROM categories").get().c;
if (count === 0) {
  const addCategory = db.prepare("INSERT INTO categories (name, description) VALUES (?, ?)");
  addCategory.run("Programming", "หนังสือเขียนโปรแกรม");
  addCategory.run("Database", "หนังสือฐานข้อมูล");

  const addBook = db.prepare(
    "INSERT INTO books (title, author, price, stock, category_id) VALUES (?, ?, ?, ?, ?)"
  );
  addBook.run("Clean Code", "Robert C. Martin", 890, 5, 1);
}

module.exports = db;   // ไฟล์อื่น (server.js) require ไปใช้ต่อ
ทำไมต้องมี PRAGMA foreign_keys = ON? SQLite ไม่บังคับ FK ให้อัตโนมัติ ถ้าไม่เปิด ตารางจะยอมให้ใส่ category_id = 999 ที่ไม่มีอยู่จริงได้ — เปิดแล้วจะ error ทันที ซึ่งนั่นคือสิ่งที่เราต้องการ

รันเพื่อสร้างฐานข้อมูล

ปกติ server.js จะ require("./db") ตอนเริ่มระบบ — ตารางจะถูกสร้างให้อัตโนมัติ ถ้าอยากสร้าง/seed ล่วงหน้าก่อนเปิด server ก็รันไฟล์นี้ตรง ๆ ได้ (รันซ้ำไม่พัง เพราะมี IF NOT EXISTS)

node db.js # ไม่มี output = สำเร็จ (ปกติของสคริปต์แบบนี้) dir *.db library.db 1,234,567 bytes
ต้องเห็น: ไฟล์ library.db เกิดขึ้นในโฟลเดอร์โปรเจกต์ ถ้าไม่เกิด = มี error ใน SQL ให้อ่านบรรทัดแรกของ error (มักเป็น SQLITE_ERROR: near "...")
ห้ามลืม: คอลัมน์ cover_url ต้องมีตั้งแต่ตอนสร้างตาราง ถ้าลืมแล้วค่อยมาเพิ่มทีหลัง ต้อง ALTER TABLE หรือลบ DB ทิ้งแล้วสร้างใหม่ — เสียเวลาตอนสอบ

3. Backend CRUD

ทำตารางเดียวให้ครบก่อน แล้วก็อปไปแปลง — เร็วกว่าเขียนใหม่

ลำดับการทำงานของ Express (สำคัญมาก)

request เข้ามา → ผ่าน middleware ตามลำดับที่ประกาศ → ถึง route ที่ตรงกับ method + path → ส่ง response ถ้าไม่มี route ไหนตรงเลย จะตกไปที่ตัวดัก 404

ตามรอย 1 request: จากกดปุ่มถึงเห็นข้อมูล

ตัวอย่าง: ผู้ใช้กด "บันทึกหนังสือ" — ไล่ตามลำดับนี้แล้วจะรู้ว่าถ้าพังต้องเปิดไฟล์ไหน

  1. public/index.html — มี <form id="book-form"> และ <tbody id="books-body"> (โครงที่อาจารย์ให้มา)
  2. public/app.js — submit handler: e.preventDefault() → สร้าง FormData → fetch("/api/books", { method: "POST", body: fd })
  3. server.js — middleware express.json() / multer ทำงาน → ถึง app.post("/api/books", upload.single("cover"), ...)
  4. server.js — validate ค่าที่ส่งมา → db.prepare("INSERT ...").run(...)
  5. db.js — ฐานข้อมูลรับข้อมูลลงตาราง books (ถ้า FK ผิดจะ error ที่นี่)
  6. server.js — res.status(201).json(bookRowToJson(row))
  7. public/app.js — await request(...) ได้ข้อมูล → ปิด dialog → เรียก loadBooks()
  8. public/app.js — tbody.innerHTML = ... → ผู้ใช้เห็นแถวใหม่
ถ้าพังที่ขั้นไหน อาการจะเป็นแบบนี้:
  • ขั้น 2 ไม่ทำงาน → กดปุ่มแล้วเงียบ (เปิด Console ดู error)
  • ขั้น 3 ได้ 404 → path ผิด หรือ route ยังไม่ถูกประกาศ
  • ขั้น 3 ได้ 400 → field ไม่ครบ หรือชื่อ field ไม่ตรง
  • ขั้น 4–5 ได้ 500 → SQL/DB พัง (ดู stack ใน terminal)
  • ขั้น 6–8 สำเร็จแต่ตารางว่าง → ชื่อ field ที่ frontend อ่านไม่ตรงกับ JSON
server.js (โครงหลัก) 
const path = require("node:path");
const fs = require("node:fs");
const express = require("express");
const multer = require("multer");
const db = require("./db");          // ได้ object ฐานข้อมูลกลับมา

const app = express();
const PORT = process.env.PORT || 3000;

const UPLOAD_DIR = path.join(__dirname, "uploads");
fs.mkdirSync(UPLOAD_DIR, { recursive: true });   // สร้างโฟลเดอร์ถ้ายังไม่มี (ไม่พังถ้ามีแล้ว)

app.use(express.json());                          // อ่าน JSON body → req.body
app.use(express.urlencoded({ extended: true }));  // อ่าน form แบบ urlencoded
app.use("/uploads", express.static(UPLOAD_DIR));  // เปิดให้เข้าถึงไฟล์ใน /uploads
app.use(express.static(path.join(__dirname, "public")));  // เสิร์ฟ HTML/CSS/JS

// ... routes อยู่ตรงนี้ ...

app.listen(PORT, () => console.log(`Server: http://localhost:${PORT}`));
ทำไม express.json() ต้องมาก่อน route? เพราะมันเป็น middleware ที่แปลงข้อความ JSON เป็น object แล้วใส่ใน req.body ถ้าประกาศทีหลัง route จะอ่าน req.body ไม่ทัน → ได้ undefined

ก่อนเขียน route: แปลงชื่อคอลัมน์ให้ตรงกับ frontend

ในฐานข้อมูลเราใช้ cover_url (snake_case) แต่ฝั่ง frontend ใช้ coverUrl (camelCase) ถ้าส่งแถวจาก DB ออกไปตรง ๆ ฝั่ง JS จะอ่านได้ undefined — เขียนตัวแปลงไว้ที่เดียวแล้วเรียกใช้ทุก route

server.js 
// แถวจาก DB ใช้ชื่อคอลัมน์แบบ snake_case → แปลงเป็น camelCase ให้ frontend
function bookRowToJson(row) {
  return {
    id: row.id,
    title: row.title,
    author: row.author,
    price: row.price,
    stock: row.stock,
    coverUrl: row.cover_url,                  // ⚠ จุดที่คนลืมบ่อย
    categoryId: row.category_id,
    categoryName: row.category_name ?? null,  // มาจาก JOIN (ถ้าไม่มีให้เป็น null)
    createdAt: row.created_at,
  };
}
ถ้าไม่แปลง: frontend จะได้ undefined ตอนอ่าน book.coverUrl → รูปไม่ขึ้น / ตารางแสดงค่าว่าง ทั้งที่ในฐานข้อมูลมีข้อมูลครบ

GET — ดึงรายการทั้งหมด (พร้อม JOIN + ค้นหา + แบ่งหน้า)

server.js 
app.get("/api/books", (req, res) => {
  // 1) อ่านค่าจาก query string: /api/books?search=clean&category_id=1&page=2
  const search = (req.query.search || "").trim();
  const page  = Math.max(1, Number(req.query.page) || 1);
  const limit = Math.min(100, Math.max(1, Number(req.query.limit) || 20));
  const offset = (page - 1) * limit;   // ข้ามไปกี่แถว

  // 2) ประกอบ WHERE แบบมีเงื่อนไข (ต้องใช้ ? เท่านั้น ห้ามต่อ string)
  const where = [];
  const params = [];
  if (search) {
    where.push("(b.title LIKE ? OR b.author LIKE ?)");
    params.push(`%${search}%`, `%${search}%`);
  }
  if (Number(req.query.category_id)) {          // กรองตามหมวด (ถ้าส่งมา)
    where.push("b.category_id = ?");
    params.push(Number(req.query.category_id));
  }
  const whereSql = where.length ? `WHERE ${where.join(" AND ")}` : "";

  // 3) นับทั้งหมดก่อน (ไว้คำนวณจำนวนหน้า)
  const total = db.prepare(`SELECT COUNT(*) AS c FROM books b ${whereSql}`).get(...params).c;

  // 4) ดึงข้อมูลจริง + JOIN เอาชื่อหมวดหมู่มาด้วย
  const rows = db.prepare(`
    SELECT b.*, c.name AS category_name
    FROM books b
    JOIN categories c ON c.id = b.category_id
    ${whereSql}
    ORDER BY b.id DESC
    LIMIT ? OFFSET ?
  `).all(...params, limit, offset);

  // 5) ส่งกลับเป็น object ที่มีข้อมูล + ข้อมูลแบ่งหน้า
  //    rows.map(bookRowToJson) = แปลงทีละแถวให้ชื่อ field ตรงกับ frontend
  res.json({ data: rows.map(bookRowToJson), page, limit, total, totalPages: Math.ceil(total / limit) });
});
ทำไมต้อง ? ไม่ใช่ต่อ string ตรง ๆ? เพราะถ้าต่อ string แล้วผู้ใช้พิมพ์ ' OR 1=1 -- จะกลายเป็น SQL injection การใช้ ? ทำให้ไลบรารีจัดการ escape ให้ปลอดภัย

    "INSERT INTO books (title, author, price, stock, cover_url, category_id) VALUES (?,?,?,?,?,?)"

app.put("/api/books/:id", upload.single("cover"), (req, res) => {
  const id = Number(req.params.id);
  const existing = db.prepare("SELECT * FROM books WHERE id = ?").get(id);
  if (!existing) return res.status(404).json({ message: "ไม่พบหนังสือ" });

  const { title, author, price, stock, category_id } = req.body;
  if (!title || !author || !category_id) return res.status(400).json({ message: "ข้อมูลไม่ครบ" });

  // ถ้าไม่ได้อัปโหลดรูปใหม่ ให้ใช้รูปเดิม
  const coverUrl = req.file ? `/uploads/${req.file.filename}` : existing.cover_url;

  db.prepare(`
    UPDATE books SET title=?, author=?, price=?, stock=?, cover_url=?, category_id=? WHERE id=?
  `).run(title, author, Number(price) || 0, Number(stock) || 0, coverUrl, Number(category_id), id);

  const row = db.prepare(`
    SELECT b.*, c.name AS category_name
    FROM books b JOIN categories c ON c.id = b.category_id
    WHERE b.id = ?
  `).get(id);

  res.json(bookRowToJson(row));
});

app.delete("/api/books/:id", (req, res) => {
  const id = Number(req.params.id);
  const book = db.prepare("SELECT * FROM books WHERE id = ?").get(id);
  if (!book) return res.status(404).json({ message: "ไม่พบหนังสือ" });

  if (book.cover_url) {

  • Number(info.lastInsertRowid) — ค่าที่ได้เป็น BigInt เอาไปใส่ JSON ตรง ๆ ไม่ได้

ทำไมต้องใช้ multer

ไฟล์ที่ส่งผ่านฟอร์มจะมาในรูปแบบ multipart/form-data ซึ่งเป็นข้อมูลหลายส่วนติดกัน express.json() อ่านไม่ได้ — multer คือ middleware ที่แกะมันออกมาเป็น req.file (ไฟล์เดี่ยว) หรือ req.files (หลายไฟล์)

ฝั่ง server

server.js 
const multer = require("multer");

// 1) กำหนดว่าจะเก็บไฟล์ที่ไหน และตั้งชื่อไฟล์อย่างไร
const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, UPLOAD_DIR),   // โฟลเดอร์ปลายทาง
  filename: (req, file, cb) => {
    const ext = path.extname(file.originalname).toLowerCase();  // ".png"
    const base = path.basename(file.originalname, ext)
      .replace(/[^a-zA-Z0-9ก-๙_-]/g, "_")     // กันอักขระแปลกในชื่อไฟล์
      .slice(0, 40);
    cb(null, `${Date.now()}-${base}${ext}`);   // เติมเวลาเพื่อไม่ให้ชื่อซ้ำ
  },
});

// 2) สร้าง middleware พร้อมข้อจำกัด
const upload = multer({
  storage,
  limits: { fileSize: 2 * 1024 * 1024 },      // 2 MB
  fileFilter: (req, file, cb) => {
    const ok = ["image/png", "image/jpeg", "image/webp", "image/gif"].includes(file.mimetype);
    if (!ok) return cb(new Error("อนุญาตเฉพาะไฟล์รูปภาพ"));
    cb(null, true);                             // true = ยอมรับไฟล์นี้
  },
});

// 3) เปิดให้เบราว์เซอร์เข้าถึงไฟล์ที่อัปโหลดแล้ว
app.use("/uploads", express.static(UPLOAD_DIR));

// 4) ใช้ใน route — ชื่อ "cover" ต้องตรงกับฝั่ง client
app.post("/api/books", upload.single("cover"), (req, res) => {
  const coverUrl = req.file ? `/uploads/${req.file.filename}` : null;
  // ... insert ลง DB ตามปกติ แล้วเก็บ coverUrl ลงคอลัมน์ cover_url
});

public/app.js 
const API = "/api";

// helper: เรียก fetch แล้วแปลง JSON + โยน error ถ้า status ไม่ใช่ 2xx
async function request(url, options = {}) {
  const res = await fetch(url, options);
  if (res.status === 204) return null;                 // DELETE สำเร็จ ไม่มี body

  const isJson = (res.headers.get("content-type") || "").includes("application/json");
  const body = isJson ? await res.json() : null;

  if (!res.ok) throw new Error(body?.message || `HTTP ${res.status}`);
  return body;
}

async function loadBooks() {
  const { data } = await request(`${API}/books`);      // GET
  const tbody = document.querySelector("#books-body");

  tbody.innerHTML = data.map((b) => `
    <tr>
      <td>${b.coverUrl ? `<img class="thumb" src="${b.coverUrl}">` : "ไม่มีรูป"}</td>
      <td>${escapeHtml(b.title)}</td>
      <td>${escapeHtml(b.author)}</td>
      <td>${b.price}</td>
      <td>
        <button data-edit="${b.id}">แก้ไข</button>
        <button data-del="${b.id}">ลบ</button>
      </td>
    </tr>`).join("");
}

// กัน XSS: แปลงอักขระพิเศษก่อนยัดลง innerHTML
function escapeHtml(str) {
  return String(str ?? "").replace(/[&<>"']/g, (c) => ({
    "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;",
  }[c]));
}
ทำไมต้อง escapeHtml? ถ้าชื่อหนังสือมี <script> แล้วเราเอาไปต่อใน innerHTML ตรง ๆ โค้ดนั้นจะถูกสั่งให้ทำงาน (XSS) — และยังทำให้หน้าพังเมื่อมีเครื่องหมาย < ในชื่อ

9. Git: commit & ส่งงาน

ข้อสอบบอกให้ clone repo → แปลว่าตอนจบต้องส่งงานกลับเป็น git เช่นกัน

ลำดับคำสั่งที่ใช้จริง

# 1) ดูว่าแก้อะไรไปบ้าง (ยังไม่ต้อง commit) git status modified: server.js modified: db.js Untracked files: study/ # 2) เลือกไฟล์ที่จะ commit (`.` = ทั้งโฟลเดอร์ปัจจุบัน) git add . git status Changes to be committed: ... # 3) บันทึกเป็น commit พร้อมข้อความสั้น ๆ git commit -m "feat: books CRUD + cover upload" [main 1a2b3c4] feat: books CRUD + cover upload # 4) ส่งขึ้น remote (ถ้าอาจารย์ให้ push) git push To https://... HEAD -> main
ทำไมต้อง git add ก่อน git commit?
  • git add = เลือกไฟล์ที่จะเข้า commit (staging area)
  • git commit = บันทึก snapshot ของไฟล์ที่เลือกไว้
  • git push = ส่ง commit ขึ้น server (GitHub/GitLab)
ก่อน commit ต้องเห็น: git status ไม่มี node_modules/ หรือ *.db อยู่ในรายการ — ถ้ามี แปลว่า .gitignore ยังไม่ถูกต้อง

ถ้า push ไม่ได้

errorสาเหตุ / วิธีแก้
fatal: not a git repository ยังไม่ได้ git init หรืออยู่ผิดโฟลเดอร์ → pwd แล้ว cd เข้าโปรเจกต์
fatal: remote origin already exists มี remote อยู่แล้ว → git remote -v ดู แล้ว git remote set-url origin <url>
Authentication failed token/รหัสผ่านผิด — ใช้ Personal Access Token แทนรหัสผ่าน หรือ login ผ่าน credential manager
rejected (fetch first) remote มี commit ใหม่ → git pull --rebase แล้ว git push อีกครั้ง
nothing to commit, working tree clean ไม่ได้แก้อะไรจริง หรือลืม save ไฟล์ใน editor (Ctrl+S)
อย่า commit ของที่ไม่มีประโยชน์: node_modules/, *.db, uploads/* (เก็บแค่ .gitkeep), ไฟล์ .env ที่มีรหัสผ่าน — ตรวจใน .gitignore ก่อนทุกครั้ง

② Client Component — ฟอร์ม + upload

"use client";   // ⚠ ต้องเป็นบรรทัดแรก ถ้าใช้ useState / onClick

import { useState } from "react";
import { useRouter } from "next/navigation";

export default function BookForm() {
  const router = useRouter();
  const [error, setError] = useState("");

  async function onSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault();                       // กันหน้า reload
    const form = e.currentTarget;
    const fd = new FormData(form);            // เก็บทุก input ที่มี name=

    const res = await fetch("/api/books", { method: "POST", body: fd });
    const body = await res.json().catch(() => null);

    if (!res.ok) return setError(body?.message || "บันทึกไม่สำเร็จ");

    form.reset();
    router.refresh();                         // สั่ง Server Component โหลดข้อมูลใหม่
  }

  return (
    <form onSubmit={onSubmit}>
      <input name="title" placeholder="ชื่อหนังสือ" required />
      <input name="author" placeholder="ผู้แต่ง" required />
      <input name="category_id" type="number" required />
      <input name="cover" type="file" accept="image/*" />
      <button>บันทึก</button>
      {error && <p style={{ color: "red" }}>{error}</p>}
    </form>
  );
}

③ API route ใน Next (ถ้าไม่แยก Express)

ถ้าให้ทำ API ในโปรเจกต์ Next เลย ให้สร้างไฟล์ตาม path — ชื่อโฟลเดอร์ = URL

app/api/books/route.ts 
import { NextResponse } from "next/server";
// สมมติมี helper DB ของเราเอง (node:sqlite / Prisma)
import { listBooks, createBook } from "@/lib/db";

// GET /api/books
export async function GET() {
  return NextResponse.json({ data: listBooks() });
}

// POST /api/books (multipart/form-data)
export async function POST(req: Request) {
  // ⚠ Next ใช้ Web API ไม่ใช่ Express: ไม่มี req.body / req.file
  const form = await req.formData();
  const title = String(form.get("title") || "");
  const author = String(form.get("author") || "");
  const file = form.get("cover");            // File | null

  if (!title || !author) {
    return NextResponse.json({ message: "ข้อมูลไม่ครบ" }, { status: 400 });
  }

  let coverUrl: string | null = null;
  if (file && typeof file !== "string") {
    const buf = Buffer.from(await file.arrayBuffer());
    const name = `${Date.now()}-${file.name}`;
    const fs = await import("node:fs/promises");
    await fs.writeFile(`public/uploads/${name}`, buf);   // ต้องมีโฟลเดอร์นี้อยู่
    coverUrl = `/uploads/${name}`;
  }

  const book = createBook({ title, author, coverUrl });
  return NextResponse.json(book, { status: 201 });
}
3 กับดักของ Next.js ที่คนย้ายจาก Express พลาดบ่อย:
  • ลืม "use client" แล้วใช้ useState → error “useState only works in Client Component”
  • Server Component เรียก fetch("/api/books") → Failed to parse URL (ต้องใส่ http://localhost:3000)
  • เขียนไฟล์ลง public/uploads แล้วหาไม่เจอ → ต้องสร้างโฟลเดอร์ก่อน และบน deploy บางที่มี public แบบ read-only
