แก้ error & ปรับโจทย์

เวลาสอบ 4 ชั่วโมง ไม่มีเวลาไล่อ่านทุกบรรทัด — หน้านี้จะสอนอ่าน error ให้เร็ว, รู้ว่าชิ้นส่วนไหนต้องทำงานคู่กัน และเจอโจทย์แบบไหนให้หยิบอะไรไปใช้

อ่าน error ให้เป็น (3 ชั้น)

error จะโผล่ที่ใดที่หนึ่งใน 3 ที่นี้ — รู้ว่าดูที่ไหน = แก้เร็วขึ้นครึ่ง

1

Terminal ที่รัน server

error ฝั่ง backend ทั้งหมดจะอยู่ที่นี่ — stack trace อ่านจากบนลงล่าง:

TypeError: Cannot read properties of undefined (reading 'filename') at D:\exam\server.js:42:25 at Layer.handle [as handle_request] (...)
อ่านแบบนี้: บรรทัดแรก = อาการ, บรรทัดที่มี path ของเรา (server.js:42) = จุดที่พัง — บรรทัดที่เหลือเป็นของไลบรารี ไม่ต้องอ่าน
2

Browser Console (F12 → Console)

error ฝั่ง frontend, JS พัง, fetch ล้มเหลว จะอยู่ที่นี่

เปิดยังไง: กด F12 หรือคลิกขวา → Inspect → แท็บ Console
สีแดง = error, สีเหลือง = warning (มักไม่ทำให้พัง)
3

Network tab (F12 → Network)

ใช้เมื่อ "หน้าเว็บขึ้นแต่ข้อมูลไม่มา" — ดูว่า request ที่ยิงไปได้ status อะไร

เห็นอะไรหมายถึง
status 200 แต่ตารางว่างข้อมูลมาถูก แต่ JS render ผิด (ดู Console)
status 404path ผิด หรือ route ยังไม่ถูกประกาศ
status 400ข้อมูลที่ส่งไปไม่ครบ/ผิดรูปแบบ
status 500server พัง → ไปดู terminal
(failed) net::ERR_CONNECTION_REFUSEDserver ไม่ได้รัน / พอร์ตผิด
CORS errorคนละ origin → ต้องเพิ่ม cors() ที่ backend
เทคนิค: คลิกที่ request → แท็บ Payload ดูว่าส่งอะไรไป และ Response ดูว่ากลับมาอะไร — 90% ของบั๊ก API อยู่สองแท็บนี้
ลำดับการไล่บั๊กที่เร็วที่สุด: ① Console มี error แดงไหม → ② Network status อะไร → ③ ถ้า 500 ให้ไปดู terminal → ④ ถ้า 200 แต่ไม่แสดงผล ให้ console.log(data) ดูว่าข้อมูลหน้าตาเป็นอย่างไร

เห็นอาการแบบนี้ → เปิดไฟล์นี้ก่อน

ตารางนี้ใช้ตอน \"output ออกมาผิด\" — ไล่จากอาการไปหาบรรทัดที่ต้องแก้

อาการที่เห็นเปิดดูที่สาเหตุที่พบบ่อย
เปิด localhost:3000 แล้วขึ้น ERR_CONNECTION_REFUSED terminal ที่รัน server server ดับไปแล้ว / ยังไม่รัน / พอร์ตไม่ใช่ 3000
หน้าเว็บขึ้นแต่ไม่มีสี ไม่มีสไตล์ server.js บรรทัด express.static(...public) path ชี้ผิดโฟลเดอร์ หรือชื่อไฟล์ CSS ไม่ตรง
ตารางขึ้นแต่ไม่มีข้อมูล (ว่างเปล่า) public/app.js ฟังก์ชันโหลด + แท็บ Network fetch path ผิด, field ที่อ่านไม่ตรงชื่อ, ลืม await
กดปุ่ม \"บันทึก\" แล้วเงียบ ไม่มีอะไรเกิดขึ้น public/app.js ส่วน addEventListener(\"submit\") id ฟอร์มไม่ตรง, ลืม e.preventDefault(), ปุ่มอยู่นอก form
กดบันทึกแล้วได้ 400 server.js route POST (ส่วน validate) ส่ง field ไม่ครบ / ชื่อ field ไม่ตรง / ค่าว่าง
กดบันทึกแล้วได้ 500 terminal (stack trace) + route นั้นใน server.js SQL ผิด, คอลัมน์ไม่มีจริง, แปลง type ผิด
อัปโหลดแล้วรูปเป็น broken image server.js (/uploads static) + ค่า cover_url ไม่ได้เสิร์ฟโฟลเดอร์ uploads / เก็บ path ผิด / field ไม่ตรง
ลบหมวดหมู่แล้วได้ 409 server.js route DELETE categories ยังมีหนังสืออยู่ในหมวดนั้น (FK บล็อกไว้) — ถูกต้องแล้ว
รีสตาร์ท server แล้วข้อมูลหายหมด db.js ค่า DB_PATH ใช้ :memory: หรือเขียน DB คนละไฟล์ทุกครั้ง
แก้โค้ดแล้วผลไม่เปลี่ยน terminal ที่รัน server ยังไม่รีสตาร์ท — ใช้ node --watch server.js หรือกด Ctrl+C แล้วรันใหม่
เปิด /api/books แล้วได้ HTML กลับมา server.js ลำดับ route + ตัวดัก 404 path ผิด / ถูก static handler ตอบก่อน / route ยังไม่ถูกประกาศ
แก้ข้อมูลแล้วค่ากลับเป็นค่าเดิม server.js route PUT ลืมส่ง field ใน UPDATE / ใช้ req.body ที่ว่างเพราะไม่มี multer หรือ json

รวม error ที่เจอบ่อย

เจอข้อความคล้าย ๆ นี้ให้กระโดดมาที่การ์ดนั้น

A. error ใน terminal

'node' is not recognized as an internal or external command

สาเหตุ ยังไม่ได้ติดตั้ง Node.js หรือติดตั้งแล้วแต่ยังไม่รีสตาร์ท terminal

แก้ ติดตั้ง Node LTS จาก nodejs.org → ปิด terminal เปิดใหม่ → node -v

Error: ENOENT: no such file or directory, open 'package.json'

สาเหตุ รัน npm ในโฟลเดอร์ที่ไม่มี package.json

แก้ pwd ดูว่าอยู่ไหน → cd เข้าโฟลเดอร์โปรเจกต์ (ที่เห็น package.json)

Error: Cannot find module 'express'

สาเหตุ ยังไม่ npm install หรืออยู่ผิดโฟลเดอร์

แก้ รัน npm install ในโฟลเดอร์ที่มี package.json แล้วรันใหม่

Error: Cannot find module './db'

สาเหตุ require("./db") แล้วไม่มีไฟล์ db.js ข้าง ๆ หรือชื่อผิด

แก้ เช็กชื่อไฟล์ (ตัวพิมพ์เล็ก/ใหญ่สำคัญ) และว่า db.js อยู่โฟลเดอร์เดียวกับ server.js

Error: listen EADDRINUSE: address already in use :::3000

สาเหตุ มีโปรแกรมอื่นใช้พอร์ต 3000 อยู่ (มักเป็น server เก่าที่ไม่ได้ปิด)

แก้ ไปที่ terminal ของ server เก่าแล้วกด Ctrl+C หรือรันพอร์ตใหม่ set PORT=3001 && npm start

SyntaxError: Unexpected token '}' / Unexpected end of input

สาเหตุ วงเล็บปีกกา/วงเล็บกลม/backtick ไม่ครบคู่

แก้ ดูเลขบรรทัดที่ error บอก — มักพังก่อนหน้าบรรทัดนั้น 1–2 บรรทัด ให้ไล่วงเล็บในฟังก์ชันนั้น

SqliteError: no such table: books

สาเหตุ ยังไม่ได้สร้างตาราง หรือเปิดคนละไฟล์ DB

แก้ รันสคริปต์สร้าง DB ก่อน (node db.js) และเช็กว่า DB_PATH ชี้ไฟล์เดียวกันทุกครั้ง

SqliteError: FOREIGN KEY constraint failed

สาเหตุ ใส่ category_id ที่ไม่มีอยู่ในตาราง categories หรือพยายามลบหมวดที่ยังมีหนังสือ

แก้ ตรวจว่า id ที่ส่งมามีจริง (ยิง GET ดู) — ถ้าเป็นการลบ ให้ลบหนังสือในหมวดนั้นก่อน

TypeError: Cannot read properties of undefined (reading 'filename')

สาเหตุ req.file เป็น undefined — ไม่มีไฟล์ส่งมา หรือชื่อ field ไม่ตรง

แก้ เทียบ upload.single("cover") กับ fd.append("cover", file) ให้ตรงกัน และอย่าลืม enctype ถ้าใช้ form ปกติ

MulterError: Unexpected field

สาเหตุ client ส่ง field ชื่อหนึ่ง แต่ server ตั้ง upload.single("อีกชื่อ")

แก้ ทำชื่อให้ตรงกันทั้งสองฝั่ง (เช่น cover ทั้งคู่)

MulterError: File too large

สาเหตุ ไฟล์ใหญ่กว่า limits.fileSize

แก้ เพิ่ม limit หรือบีบรูปก่อนอัปโหลด (แต่ระวังหน่วยเป็น byte)

B. error ใน browser

TypeError: Failed to fetch

สาเหตุ server ไม่ได้รัน, URL ผิด, หรือเรียกข้าม origin แล้วติด CORS

แก้ เปิด http://localhost:3000/api/books ตรง ๆ ก่อน — ถ้าเปิดได้แต่ fetch ไม่ได้ แปลว่า path/port ผิด

Uncaught (in promise) SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON

สาเหตุ res.json() แต่ server ตอบ HTML (มักเป็นหน้า 404) กลับมา

แก้ path ของ API ผิด หรือ server ยังไม่มี route นั้น → ดู Network ว่า status เป็น 404 ไหม

TypeError: Cannot read properties of null (reading 'addEventListener')

สาเหตุ document.querySelector("#...") หา element ไม่เจอ (id ไม่ตรง หรือ script ถูกโหลดก่อน HTML)

แก้ ตรวจ id ใน HTML ให้ตรงกับ JS และวาง <script> ไว้ท้าย <body> หรือใช้ DOMContentLoaded

กด Submit แล้วหน้าเว็บรีโหลด/ค่าหาย

สาเหตุ ลืม e.preventDefault() ใน submit handler

แก้ ใส่เป็นบรรทัดแรกของ handler

รูปที่อัปโหลดขึ้นเป็น broken image (404)

สาเหตุ ไม่ได้ประกาศ express.static(UPLOAD_DIR) หรือเก็บ path ผิด

แก้ เพิ่ม app.use("/uploads", express.static(UPLOAD_DIR)) และเก็บค่าเป็น /uploads/ชื่อไฟล์

ตารางไม่รีเฟรชหลังเพิ่ม/ลบ

สาเหตุ ไม่ได้เรียกฟังก์ชันโหลดใหม่หลัง API สำเร็จ

แก้ await loadBooks() หลัง await request(...) ทุกครั้ง

req.body เป็น undefined (ฝั่ง server)

สาเหตุ ลืม app.use(express.json()) หรือ client ไม่ได้ส่ง Content-Type: application/json

แก้ ประกาศ middleware ก่อน route และเช็ก header ใน Network tab

ตาราง HTTP status

Codeความหมายสาเหตุที่พบบ่อย
200OKอ่าน/แก้ไขสำเร็จ
201Createdสร้างสำเร็จ (ควรตอบหลัง POST)
204No Contentลบสำเร็จ — ห้ามมี body
301Moved PermanentlyURL เก่าถูกย้ายถาวร (เช่น redirect หลังเปลี่ยนโดเมน)
304Not Modifiedข้อมูลไม่เปลี่ยน — ให้เบราว์เซอร์ใช้ cache เดิม
400Bad Requestvalidate ไม่ผ่าน, field หาย, ไฟล์ผิดชนิด
401Unauthorizedยังไม่ล็อกอิน / token หาย
403Forbiddenล็อกอินแล้วแต่ไม่มีสิทธิ์
404Not Foundpath ผิด หรือ id ไม่มีใน DB
409Conflictชื่อซ้ำ (UNIQUE) หรือลบ parent ที่มี child
429Too Many Requestsยิงถี่เกิน rate limit
500Internal Server Errorโค้ดพัง — ดู stack ใน terminal
502Bad Gatewayproxy/gateway ติดต่อ backend ไม่ได้
503Service Unavailableserver กำลัง restart / รับงานเกิน
504Gateway Timeoutbackend ตอบช้าเกินกำหนด
กฎที่อาจารย์ชอบถาม: POST สำเร็จ = 201, DELETE สำเร็จ = 204, หา id ไม่เจอ = 404, ข้อมูลผิด = 400 — สี่ตัวนี้พอสำหรับข้อสอบปฏิบัติ
Idempotency (ออกข้อกาบ่อย): GET, PUT, DELETE เป็น idempotent (เรียกซ้ำผลลัพธ์เหมือนเดิม) ส่วน POST และ PATCH ไม่ idempotent

เจอโจทย์แบบนี้ หยิบอะไรไปใช้

ข้อสอบจะเปลี่ยนโดเมน — โครงโค้ดเดิมใช้ซ้ำได้แทบทั้งหมด

โจทย์บอกว่า…หยิบจากไหนเปลี่ยนอะไร
CRUD 2 ตาราง + รูปภาพ ทั้งโปรเจกต์นี้ (categories → books + multer) เปลี่ยนชื่อตาราง/field ตามโจทย์
books 1:N reviews โครง categories → books สลับบทบาท: books เป็นตารางแม่, reviews มี book_id
products / orders โครงเดิม + ตารางกลาง orders 1:N order_items N:1 products (many-to-many ต้องมีตารางกลาง)
users / posts โครงเดิม posts.user_id → users.id, เพิ่ม avatar upload
มี HTML/CSS ให้แล้ว เหลือ JS บท 5 Frontend เปิด HTML ดู id จริงก่อน แล้วผูก selector ให้ตรง
มี Swagger/OpenAPI ให้ บท 7 Codegen อ่าน paths + schemas แล้วgen หรือวางโครงตาม
ให้ใช้ Prisma บท 6 เขียน schema.prisma → npx prisma db push → เปลี่ยน query เป็น prisma.x.findMany()
ให้อัปโหลดหลายไฟล์ บท 4 upload.array("images", 5) + req.files + วนลูปบันทึก
ให้ค้นหา + แบ่งหน้า GET /api/books LIKE ? + LIMIT ? OFFSET ? + ส่ง total/totalPages กลับ
ให้ seed ข้อมูล db.js เขียน INSERT 3–5 แถวใน if (count === 0)
ให้ Docker บท 8 Dockerfile + compose (port + volume)
ให้ทำ Next.js แนวคิดเดียวกับ frontend fetch จาก client component หรือ await fetch ใน server component
หลักคิด: เปลี่ยนแค่ 3 อย่าง — ① ชื่อตาราง/field ② จำนวนตาราง ③ ที่เก็บไฟล์ ที่เหลือ (route, validate, status code, fetch, render) คือสูตรเดิมทั้งหมด
